# Tareas del laboratorio 2.4

Elige una sola. Las tareas A y B se resuelven con un agente local. Las tareas C y D, con una
instrucción reutilizable.

Ninguna de las cuatro está resuelta por los artefactos que ya trae el repositorio en
`.github/`. Si al construir la tuya notas que se parece demasiado a uno de ellos, conversa
con el relator antes de seguir.

## A. Agente de soporte comercial

El área comercial recibe llamadas de comercios que no entienden su liquidación. Hace falta
un agente que explique, en lenguaje de negocio y sin jerga técnica, cómo se compuso la
liquidación de un comercio en un periodo: comisiones, tope, contracargos y retención. No
toca código ni archivos. Responde con el formato que usa el área comercial en sus correos.

## B. Agente redactor de pull requests

El equipo pierde tiempo escribiendo descripciones de pull request que después nadie lee.
Hace falta un agente que, a partir de los cambios del repositorio, redacte el título y la
descripción con la plantilla del equipo: qué cambia, por qué, cómo se verificó y qué
riesgo tiene. No modifica código.

## C. Instrucción para la documentación del equipo

Los documentos Markdown que produce el equipo salen cada uno con un estilo distinto. Hace
falta una instrucción que se aplique sola a los entregables de los laboratorios
(`labs/**/entregables/**/*.md`) y fije la estructura, el tono, cómo se citan archivos y
líneas, y qué no se escribe nunca.

## D. Instrucción para los scripts de Git Bash

Los scripts del equipo corren en Git Bash sobre Windows y fallan de formas difíciles de
diagnosticar. Hace falta una instrucción que se aplique sola a `scripts/**/*.sh` y fije las
convenciones: códigos de salida, compatibilidad con Git Bash, macOS y Linux, mensajes de
error y qué no usar.
